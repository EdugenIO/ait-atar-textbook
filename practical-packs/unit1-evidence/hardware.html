Worked decisions

Fictional repair café brief: residents must find what to bring, the date, venue and next action. The decisions below model reasoning; they are not observed learner results.

FocusDecision and explanation
Components and CPUMicrophone supplies input; CPU executes editing instructions; RAM holds active work; headphones provide output; SSD retains the saved project. A CPU is not the whole computer.
Memory purpose and typesRAM is normally volatile primary memory; ROM can hold firmware without power; SSD/HDD/USB are secondary storage. Saving and extra RAM solve different problems.
PeripheralsChoose microphone/headphones for recording, scanner for paper input and printer for physical output; verify connection and software support.
System categoriesA desktop suits the fixed editing desk, a mobile device supports field capture and a server provides shared services. A category alone does not prove compatibility.
Named OS examplesWindows, macOS (syllabus: Mac OS) and Linux can support desktop work; iOS and Android are mobile examples. iPadOS is a modern clarification, not a replacement for the named iOS requirement.
Four OS functionsThe interface accepts a save command; CPU/memory scheduling manages resources; file permissions manage access; process support allows the editor to run. These are OS functions, not the editor’s audio effects.
Older software on newer hardwareAn old editor requires an unsupported OS/API. Faster hardware does not repair that compatibility failure.
New software on older hardwareA new editor requires 8 GB RAM and supported OS X; a fictional older machine has 4 GB and an unsupported OS. Storage capacity cannot satisfy either failure.
Selection criteriaCheck the exact version’s OS, processor, RAM, free storage and peripheral requirements first, then test recording/export with a representative file. Unknown requirements remain unknown.

Apply independently

Prepare a selection table for a fictional recording task. Trace input/CPU/memory/output/storage, assign a peripheral by function, compare desktop/mobile/server roles, name all five syllabus OS examples and explain the four OS functions. Test two supplied compatibility scenarios before recommending a system.

Use this as part of the existing chapter task, not an additional assessed project or extra lesson. Predict outcomes, create/inspect the required output and record the actual result.
