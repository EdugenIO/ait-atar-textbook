Maintenance lab guide

Open the lab

Task and expected observations

  1. Select Downloads and preview. The scenario must block cleanup because approval is absent. This models a decision, not a universal rule that Downloads can never be cleaned.
  2. Deselect Downloads. Select previews and cache; predict 500 MB reclaimed. Apply without confirmation: expect a review message and unchanged space.
  3. Confirm the review and apply. Expect 2,500 MB free. Apply again after reviewing: expect 0 additional MB, not another 500.
  4. Try traditional defragmentation on the SSD: it must not apply. Compare the HDD and drive-aware choices. Explain why the operation is not a cure for every slowdown.
  5. Run the virtual scan and quarantine its flagged sample. Explain why a scan result is limited.
  6. Remove the virtual record, then restore it. Expect version 1, not version 2. Explain the recovery-point limit.
  7. Export the log and explain one choice. Reset clears this page’s temporary model.

Supervised real-tool follow-up

The simulation is operational practice with a model. It does not certify that a learner has used an actual OS utility.

  1. Use only a teacher-approved disposable VM, training account or sandbox with an appropriate snapshot/backup. Record the OS version and drive type.
  2. Under supervision, open the OS storage/temporary-file report. Inspect categories and record sizes. Preview before applying; preserve downloads, source files and any category without approval.
  3. If authorised for that disposable environment, remove only the specifically approved disposable category, then record before/after space. Do not extrapolate its size or performance to another device.
  4. Inspect the OS drive-optimisation information and its reported media type. Use the OS’s drive-aware recommendation under the teacher’s procedure. Do not force traditional HDD operations onto SSDs.
  5. Inspect the approved protection tool’s update/scan history and permissions. No malware, disabling protection or unapproved utility installation is required.
  6. Record observations, limits and teacher-approved next actions. If no suitable sandbox is available, retain the skill as unverified rather than reporting the simulation as real OS use.
