Choose tools and preserve a shared decision record

Unit 3 · fictional community-festival client brief. Read the chapter explanation first. These are worked decisions, not observed learner results.

Worked decisions

FocusDecision and explanation
PhysicalA shared-room prototype review supports immediate discussion and shared equipment; travel, room availability and access can exclude participants. Keep a written decision record.
VirtualAn approved shared document supports remote comments and version history; connection, permissions and software access remain dependencies. A call supports discussion but needs an accessible record of agreed actions.
Hybrid and online toolsUse an available shared document/task board for owners, versions and approval, with a short meeting for unresolved decisions. An approved browser editor may support production, but confirm supported formats, export and offline availability. No particular vendor or new account is required.
Convergence effectOne mobile tool can capture, edit and send a draft quickly. That concentrates failure and can distribute unapproved content faster. Keep approval and a copy of agreed output before handover.

Check your reasoning

Compare your explanation

No. Record the agreed version, decision, owner and remaining actions in a shared accessible record.

Production sequence

  1. Compare physical, virtual and hybrid methods for two volunteers: one remote, one with unreliable connectivity. Include advantages, disadvantages and implications for access and review.
  2. Choose an approved existing shared tool if available; otherwise rehearse roles locally and label the online-operation skill unverified. Record owner, reviewer, version, change and decision.
  3. Have a peer propose a change, review it and retain the agreed version. Test opening/exporting it in the chosen production application.
  4. Analyse one converged workflow and a failure fallback; show how an approved offline change is reconciled with the shared record.

Apply independently

Complete the production sequence using your own version of the festival brief. Change the venue and one user access need, then justify and test the resulting revision. Retain your own outputs and observations; the supplied reference is a model.

Use this within the existing chapter task, not an extra assessed project or additional teaching week. Record expected and actual results separately.

Evidence to retain

  • Keep a permissions/format/access check and actual version or review history.
  • Separate a local role rehearsal from actual operation of an online application.
  • Explain a dependency and who resolves conflicting edits.

Actual learner performance, native application output and independent teacher review remain unverified. Supplied model results must not be copied into an observed-result log.
