Unit 4 · fictional community-centre client brief. Read the chapter explanation first. These are worked decisions, not observed learner results.

Worked decisions

FocusDecision and explanation
Learning purposeThe centre wants volunteers to find the approved venue and report a fictional practice result. A short demonstration supports sequence; a text guide supports scanning/offline access; a live session supports questions but needs scheduling and an accessible alternative.
Online functionsChoose available approved features such as content pages, captions, comments, quiz feedback or revision history for the learning need. Document permissions, supported devices and what the learner actually does. A screenshot of a tool is not evidence of operating its functions.
Explain → show → try → reviewState the task, model the steps, let the learner try an equivalent example, then offer explanatory feedback and a retry. Retain control over pacing and equivalent text; avoid asking for personal information just to demonstrate a form.
Collection lifecycleDefine purpose and minimum fictional fields first. Distinguish browser validation, receiving-side validation, authorised receipt/review, export, retention and deletion. The existing response lab demonstrates these locally; it is not a deployed online service or universal production-security template.
Model versus operationThe static finished page previews a valid group size without transmission. The loopback lab receives fictional data on the local machine with restricted review. Neither by itself demonstrates approved online collection, platform permissions or the learner’s own implementation.

Apply independently

Work through these steps for your own version of the community-centre brief. Retain your own output and actual observations, separately from the supplied model.

  1. Create or adapt a short approved tutorial using explain/show/try/review and an accessible text alternative. Retain editable source and delivered output.
  2. Operate an available approved online tool and record its selected functions, roles and actual learner journey; if unavailable, leave online operation unverified.
  3. Use invented data only. Test the existing form cases and follow the loopback lab through receipt, authorised review, export/deletion and restart checks as directed.
  4. For a school-approved online trial, first confirm the receiving service, roles and handling settings with the teacher, then record actual results separately from localhost observations. Revise and retest one issue.

Use this within the existing chapter task, not an extra assessed project or additional teaching week. Record expected and actual results separately.

Evidence to retain

  • Tutorial source, output, attempt/feedback pathway and named tool/environment.
  • Trace fictional data through actual receipt/review/export/deletion where performed.
  • Approved online operation remains unverified until a separately authorised trial occurs.

Actual learner performance, native application output and independent teacher review remain unverified. Supplied model results must not be copied into an observed-result log.
