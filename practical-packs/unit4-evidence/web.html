Unit 4 · fictional community-centre client brief. Read the chapter explanation first. These are worked decisions, not observed learner results.

Worked decisions

FocusDecision and explanation
Participation and CMSVisitor contributions may add knowledge and freshness, but need consent/purpose, moderation and accuracy checks. A CMS can support draft/publish states, roles, templates and revisions; a volunteer’s draft is not approved simply because it is in the system.
HTML and web labelsHTML (.html/.htm) describes content structure; CSS controls presentation. Web 2.0 commonly describes participatory services. Web 3.0 is ambiguous: distinguish semantic/linked data from decentralised Web3 claims rather than treating them as one mandatory upgrade.
Concrete semantic exampleAn event has a stable identifier, title, start time and venue relationship that software can interpret. This is a machine-readable relationship example, not evidence that a blockchain or a particular CMS is needed. An unstructured comment remains user-generated content even without that data model.
Standards and conventionsW3C develops standards/guidelines with its community. The syllabus’s Web Design and Applications label spans HTML/CSS, graphics, audio/video, accessibility, internationalisation and mobile web; it is not a single checklist whose completion proves accessibility. Current W3C navigation may organise these topics differently.
Six application checksUse semantic headings and CSS; choose suitable graphics and useful alternatives; supply relevant media captions/text equivalents; test keyboard operation and focus; declare document/phrase language and unambiguous dates; test reflow and touch/keyboard at narrow sizes. The supplied web pack gives editable examples, not full conformance approval.
InternationalisationUTF-8 supports multiple scripts; language declarations identify text language rather than translate it. “4 May 2027” avoids the ambiguity of 04/05/2027; date markup can carry a machine-readable value. For another locale, check translated wording, text expansion, date/time conventions and direction where applicable.
Validation and compatibilityA required whole-number group size 1–20 rejects blank, 0, 21 and 2.5; 1 and 20 are boundary passes. Browser feedback is bypassable, so a receiving service needs independent validation. Passing a syntax/range rule does not prove identity or real-world truth. Repeat required tasks in named browsers and record unavailable environments as untested.

Check your reasoning

A validator reports no HTML errors. Does that establish that a visitor using a keyboard can finish the task?

Compare your explanation

No. Markup validation and task/accessibility observations answer different questions. Test the actual controls and route.

Apply independently

Work through these steps for your own version of the community-centre brief. Retain your own output and actual observations, separately from the supplied model.

  1. Copy the existing web-standards starter and implement semantic structure, graphics/media alternatives, language/date markup, labels, help and reflow as relevant to the brief.
  2. Write a small CMS draft/review/publish scenario, plus a participatory content example and a specifically defined Web 3.0 example; identify moderation and evidence limits.
  3. Test blank, invalid, fractional and boundary form values, keyboard/error recovery, narrow/wide layouts and text enlargement. Record actual results.
  4. Repeat the same tasks in a second available browser; if unavailable, leave the compatibility row unverified. Revise a failing issue and repeat its check.

Use this within the existing chapter task, not an extra assessed project or additional teaching week. Record expected and actual results separately.

Evidence to retain

  • Retain edited source, output and a six-topic standards application record.
  • Record browser/version, viewport, input method and expected/observed result.
  • Keep browser preview separate from receiving-side and approved online operation.

Actual learner performance, native application output and independent teacher review remain unverified. Supplied model results must not be copied into an observed-result log.
