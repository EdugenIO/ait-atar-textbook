Fictional response-handling lab

Follow a response from a learner form to server validation, restricted review, export and deletion. The textbook does not run a public collection service.

Run the lab locally

  1. Download and extract the pack. Use a school-approved existing Node.js runtime; do not install a runtime just to complete this exercise without approval.
  2. Open a terminal in the extracted response-lab folder and run node server.mjs.
  3. The terminal prints a learner URL and a reviewer URL. Open the learner URL first. The reviewer link contains a temporary capability key; keep it within this fictional exercise.
  4. Only the exact listed workshop and a whole-number group size are accepted. Do not enter names or other personal information.
  5. Stop the server with Ctrl+C. Records and the reviewer key exist only in that server’s memory and disappear when it stops.

What to verify

  1. Submit Design + 4: expect one accepted fictional response.
  2. Send the supplied invalid direct request for size 13: expect server rejection and no extra record, even though browser controls were bypassed.
  3. Try review access without the key: expect 403. Open the reviewer link and inspect the fictional record.
  4. Export the records; compare column names and values. No names or email columns should exist.
  5. Delete the response as reviewer, refresh and verify it is gone. Stop/restart the server and confirm both records and key are reset.

This is a small loopback teaching service, not production authentication or a deployment recipe. No accounts, grades, persistent database or external service is used.
