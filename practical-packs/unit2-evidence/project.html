Manage requirements, dependencies and a tested handover

Unit 2 · fictional bicycle-shop client brief. Read the chapter explanation first. These are worked decisions, not observed learner results.

Worked decisions

FocusDecision and explanation
Client requirementsThe fictional shop needs visitors to find services, opening hours and contact guidance. Record three testable criteria and confirm missing details.
Plan of actionApprove facts → draft page/media → review → integrate → test → revise → deliver. Each task has an owner and a concrete output.
Time/dependenciesA one-lesson edit depends on approved wording; integration depends on usable media exports. If approval slips, re-sequence independent layout work and record the scope/time decision.
ResourcesCheck available tools, source rights, staff time, devices and browser/player support. Two tasks cannot run in parallel if they require the same unavailable person or equipment.
EvaluationObserve the required task, compare against each criterion, record a specific revision and retest. Keep failed/untested separate from passed.
Design process and compliance with briefUse the chosen process to create an actual prototype. Handover includes source files, delivery files, test record, known limits and ownership of maintenance. A plan alone does not prove the delivered result meets requirements.

Apply independently

Use your small shop prototype as one existing project. Produce a requirements/check table, action plan with owners/durations/dependencies/resources and checkpoints. Build incrementally, run client-task tests, revise a meaningful issue and repeat its check. Evaluate every requirement and record a handover with remaining limitations.

Use this within the existing chapter task, not an extra assessed project or additional teaching week. Record expected and actual results separately.

Evidence to retain

  • Link requirements to actual outputs and observations.
  • Explain time/scope changes and resource conflicts.
  • Keep planning, production and evaluation records together.

Actual learner performance, native application output and independent teacher review remain unverified. Supplied model results must not be copied into an observed-result log.
