2. Understand the lesson ideas

An interface should help people complete a task. Build a clear information order, choose controls that make sense and test how the design works for different users.

Start with a festival visitor’s task

The fictional community festival guide needs to help visitors find a session, its time and its venue. Define who will use it and in what conditions: a phone outside, a shared kiosk or a screen at home. Ask which information the visitor needs first. An interface can look polished while leaving this task difficult.

Explore this concept and its visual/example support

Choose navigation for the medium

A phone guide may use labelled links and a clear route back to the programme. A kiosk may need larger touch controls and a visible route home. A control’s appearance should signal its role and its result should match its label. Keep placement and terminology consistent. Check keyboard operation and focus as well as pointer or touch use. An icon without a clear name can leave its purpose uncertain.

Language you can use in your explanation
Graphical user interface
An interface using visual components such as text, icons, menus and controls to support interaction.
Information hierarchy
An arrangement showing levels of importance or relationships between content.
Navigation control
An interface element that lets someone move between destinations or views.
Contextual help
Guidance provided near the task or control where it is needed.
Usability
How well specified users can complete their tasks effectively, efficiently and with satisfaction in a stated context.
Accessibility
Design that enables people with disabilities to perceive, understand, navigate and operate a product.

3. Follow a worked decision

A fictional festival needs a programme, usable navigation and appropriate media. A walking volunteer and a production editor have different tasks. Treat asset approval, accessibility, device evidence and project resources as explicit constraints.

Today’s decision in that case

A GUI should serve the user task and context, not only the producer’s preferred appearance.

  1. Identify: Which requirement, concept or distinction does this decision address?
  2. Explain: Which part of the reasoning supports the decision?
  3. Qualify: What condition or evidence would you need before claiming it works in practice?

The decision is a supplied teaching model. Its proposed checks are not your observed results.

Deeper chapter model: Make a session’s venue easier to find
  1. Initial design: The session title is prominent, but the venue is a small unlabeled icon at the bottom.
  2. Observed task: A trial visitor finds the session time but asks where it will be held.
  3. Analysis: The practical details are separated and the icon’s meaning is unclear.
  4. Revision: Group time and venue together and add the visible label “Venue”. Preserve a clear content hierarchy.
  5. Checks: Repeat the venue task, check keyboard access to navigation and inspect the information at narrow width.
  6. Judgement: Use the results to judge the change; record the limited trial rather than claiming complete accessibility.

The analysis connects elements, principles and interaction to an observed user need.

More support or challenge · choose if needed

Spot and correct a connected misconception

Claim to examine: A visually attractive interface is automatically usable and accessible.

Compare the correction

Appearance is one part of the design. Task completion, input methods, content structure and disability-related barriers need their own evidence.

Supported chapter question

A session card uses an unlabeled map pin. Suggest a revision and explain the evidence you would collect.

Check the supported reasoning

Add a clear venue label and meaningful location text, with an accessible name for any link. Ask a visitor to identify the venue, and check the link’s keyboard operation and name. Do not assume a familiar symbol is understood by everyone.

Related practice and explanation

Analyse

How could the same type treatment and spacing connect related session cards?

Compare an explained answer

Repeated treatments signal equivalent roles, while proximity groups each session’s title with its details. Explain the effect in relation to the visitor’s task.

Apply

What should a navigation map show beyond destinations?

Compare an explained answer

Show the routes between them, including how users return or recover. Test those routes in the implemented prototype.

Transfer and test the limits

Change one relevant client condition: audience/access need, output medium, available application, recovery need or resource limit. Explain which part of today’s decision still applies, which part changes and what new evidence you need. Choose a change that matters to this lesson rather than adding an unrelated feature.

Teaching choices and review limits

Use retrieval, explicit instruction, a worked decision, faded support, self-explanation, discussion, independent application, feedback and reflection in the core route. Optional error analysis, interleaving and transfer can replace practice when appropriate. For a learner needing support, narrow the task and retain one scaffold; for a learner ready for challenge, remove the scaffold or vary a meaningful condition. No new accounts, real personal data or purchases are required.
