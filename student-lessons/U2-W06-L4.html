2. Understand the lesson ideas

A network connects devices so people can share information and services. Plan from the business’s rooms, tasks and users, then explain the connections and their limits.

Separate topology from service organisation

A star describes how links are arranged. Client-server describes how services are organised: a server might hold shared files and manage access. Peer-to-peer sharing can avoid a dedicated server for a simple task, but permissions, availability and recovery can be harder to coordinate as a team grows. A server can itself be connected to the central switch in a star. These descriptions are not mutually exclusive alternatives.

Review the proposed LAN

Label endpoints, link media, central equipment and the internet boundary. Separate staff and visitor access in the proposal and explain who needs each service. Check port capacity, physical placement, wireless coverage, access rights and recovery arrangements. A diagram is a proposal, not proof of coverage or performance. State what a site check and representative transfer test would need to establish.

Deeper chapter model: Connect a fictional print shop
  1. Needs: Three fixed workstations, one shared printer and a mobile staff laptop.
  2. Wired links: Connect the fixed devices to a central switch using suitable copper links.
  3. Wireless link: Connect a staff access point to the LAN for the laptop, subject to a coverage check.
  4. Services: Place a file server on the LAN if central file service and access management are required. Plan backup separately.
  5. Outside connection: Use a router at the internet boundary, with service equipment appropriate to the connection.
  6. Review: Check capacity, access controls, installation constraints and an outage/recovery plan.

The recommendation follows the tasks. It combines a physical star with a possible client-server service arrangement.

More support or challenge · choose if needed

Spot and correct a connected misconception

Claim to examine: A star network and a client-server network are competing choices.

Compare the correction

One describes connection layout; the other describes service organisation. A LAN can use both.

Supported chapter question

An 80 MB file crosses a link at an ideal constant 20 Mb/s. Calculate the ideal time and name one reason the real transfer could take longer.

Check the supported reasoning

80 × 8 = 640 megabits; 640 ÷ 20 = 32 seconds. Overhead, congestion or a slower part of the route could increase the time. This is an ideal estimate, not a measured result.

Related practice and explanation

Evaluate

If the central switch fails, can the diagram guarantee normal local sharing?

Compare an explained answer

No. Devices depending on that switch can lose connectivity. Identify the dependency and plan an appropriate response rather than promising uninterrupted service.

Transfer and test the limits

Change one relevant client condition: audience/access need, output medium, available application, recovery need or resource limit. Explain which part of today’s decision still applies, which part changes and what new evidence you need. Choose a change that matters to this lesson rather than adding an unrelated feature.

Teaching choices and review limits

Use retrieval, explicit instruction, a worked decision, faded support, self-explanation, discussion, independent application, feedback and reflection in the core route. Optional error analysis, interleaving and transfer can replace practice when appropriate. For a learner needing support, narrow the task and retain one scaffold; for a learner ready for challenge, remove the scaffold or vary a meaningful condition. No new accounts, real personal data or purchases are required.
