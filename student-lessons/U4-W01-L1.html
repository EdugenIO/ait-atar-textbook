2. Understand the lesson ideas

A lost file can interrupt a whole organisation. Learn how backups, recovery plans and security controls protect information, then explain which choices fit a client’s needs.

Start with what the client must recover

A fictional community centre loses its booking computer. Staff need the booking list before they can reopen. Identify priority services, acceptable downtime and how much recent work could be lost. A disaster recovery plan records who acts, what to restore first, required equipment, contact details and how to check the result. Practise recovery with sample files so the plan is more than a document.

Check evidence before recommending a system

Use a source log: record the author, date, claim and supporting evidence. Verifiability asks whether the claim can be checked. Accuracy asks whether it is correct. Currency asks whether it is up to date for this decision. Compare relevant primary documentation and record unknowns. A recent advertisement is not automatically accurate, and an older explanation of a stable concept is not automatically unusable.

Language you can use in your explanation
Disaster recovery plan
A documented plan for restoring priority systems and data after disruption.
Audit trail
A record of events that helps trace actions and investigate changes.
Full backup
A copy of all data selected for that backup.
Differential backup
A copy of changes since the most recent full backup.
Incremental backup
A copy of changes since the previous backup in the chain.
Archive
Data kept for longer-term reference or retention rather than everyday use.

3. Follow a worked decision

A fictional community centre needs reliable activity information, a manageable online learning resource and a justified service/network proposal. Separate source approval, personal-information handling, actual operation and intended design.

Today’s decision in that case

Distinguish a recovery need, a security control and a claim about an event. Each needs its own evidence.

  1. Identify: Which requirement, concept or distinction does this decision address?
  2. Explain: Which part of the reasoning supports the decision?
  3. Qualify: What condition or evidence would you need before claiming it works in practice?

The decision is a supplied teaching model. Its proposed checks are not your observed results.

Deeper chapter model: Recover a Wednesday booking list
  1. Sunday: Make full backup F of the selected booking data.
  2. Monday: Record changes A and complete backup I1 in the incremental scheme, or D1 in the differential scheme.
  3. Tuesday: Record new changes B and complete I2, or D2. D2 includes changes since Sunday.
  4. Wednesday failure: The computer fails before another backup. The latest available recovery point is Tuesday’s completed backup.
  5. Incremental restore: Use F → I1 → I2 in order. This simple chain needs both increments.
  6. Differential restore: Use F → D2. D1 is not required for this recovery point.
  7. Check: Open sample bookings, check expected records and report any work after the recovery point as potentially lost.

These are alternative backup schemes, not instructions to mix both chains. The example assumes successful, usable backups and a supported restore process.

Spot and correct a connected misconception

Claim to examine: “Cloud storage automatically means we have a tested backup.” Is that justified?

Compare the correction

No. Check retention, deletion behaviour, protected recovery copies and a successful restore. Remote location alone does not establish recoverability.

Supported chapter question

In the example, I1 is lost but F and I2 remain. Can you assume a complete Tuesday restore?

Check the supported reasoning

No. The simple incremental chain requires I1 as well as I2. Check other recovery copies rather than claiming the chain is complete.

Teaching choices and review limits

Use retrieval, explicit instruction, a worked decision, faded support, self-explanation, discussion, independent application, feedback and reflection in the core route. Optional error analysis, interleaving and transfer can replace practice when appropriate. For a learner needing support, narrow the task and retain one scaffold; for a learner ready for challenge, remove the scaffold or vary a meaningful condition. No new accounts, real personal data or purchases are required.
