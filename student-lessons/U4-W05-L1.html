2. Understand the lesson ideas

A useful website needs clear content and dependable behaviour. Explore how people publish online, then check structure, accessibility, forms and browser compatibility.

Connect standards to the person using the site

W3C develops web standards and guidelines to support an interoperable web. The syllabus groups relevant work under Web Design and Applications: HTML/CSS, graphics, audio/video, accessibility, internationalisation and mobile web. Use an appropriate image format and text alternative; provide captions or other required media alternatives; identify the page language; allow text to resize and content to reflow. Keep controls usable with a keyboard. Conventions such as consistent navigation help people predict behaviour. A validator finding no markup errors does not prove complete accessibility or usability.

3. Follow a worked decision

A fictional community centre needs reliable activity information, a manageable online learning resource and a justified service/network proposal. Separate source approval, personal-information handling, actual operation and intended design.

Today’s decision in that case

Web conventions help interoperable, predictable use. A standards label is not a certificate that every task or access need is satisfied.

  1. Identify: Which requirement, concept or distinction does this decision address?
  2. Explain: Which part of the reasoning supports the decision?
  3. Qualify: What condition or evidence would you need before claiming it works in practice?

The decision is a supplied teaching model. Its proposed checks are not your observed results.

Deeper chapter model: Test a fictional group-size field
  1. Rule: The field is required and must contain a whole number from 1 to 20 inclusive.
  2. Empty: Reject: explain that a group size is required.
  3. 0 or 21: Reject: explain the allowed range.
  4. 1 and 20: Accept under this field’s rules: both boundaries are included.
  5. 2.5 or letters: Reject: request a whole number in the allowed range.
  6. Server check: A real collection service must repeat the rules on the server. A browser message alone cannot secure submitted data.
  7. Limit: An accepted number does not prove that this many people will actually attend.

Test valid, invalid and boundary cases. Explain what each test establishes and what it leaves unknown.

Spot and correct a connected misconception

Claim to examine: “The form accepts an email address, so the address must be real.” Is that justified?

Compare the correction

No. A format check can accept a plausible address without proving existence or ownership.

Supported chapter question

The valid range is 1–20 whole people. Why test both 20 and 21?

Check the supported reasoning

They test an allowed upper boundary and a value just outside it. The expected results are accept and reject.

Teaching choices and review limits

Use retrieval, explicit instruction, a worked decision, faded support, self-explanation, discussion, independent application, feedback and reflection in the core route. Optional error analysis, interleaving and transfer can replace practice when appropriate. For a learner needing support, narrow the task and retain one scaffold; for a learner ready for challenge, remove the scaffold or vary a meaningful condition. No new accounts, real personal data or purchases are required.
