1. Designing usable interfaces

Recall

  • How can proximity and repetition connect related information?
  • Why does a positive opinion about a page not prove a user task works?

Visual walkthrough

Make the route and information order visible

Pause and predict: Which practical details are grouped in the revised card?

Show the explanation

Time and venue sit together under the title, making their relationship explicit. Their labels reduce reliance on an unexplained icon.

Try a small change: The same guide moves to a public touch kiosk. Which assumptions need checking?

Compare your reasoning

Recheck input, control size and reach, viewing conditions and return/home routes for kiosk users. Do not assume the phone arrangement transfers unchanged.

Try it with support

A session card uses an unlabeled map pin. Suggest a revision and explain the evidence you would collect.

Example reasoning: Add a clear venue label and meaningful location text, with an accessible name for any link. Ask a visitor to identify the venue, and check the link’s keyboard operation and name. Do not assume a familiar symbol is understood by everyone.

Practise and explain

Analyse: How could the same type treatment and spacing connect related session cards?

Repeated treatments signal equivalent roles, while proximity groups each session’s title with its details. Explain the effect in relation to the visitor’s task.

Apply: What should a navigation map show beyond destinations?

Show the routes between them, including how users return or recover. Test those routes in the implemented prototype.

Evaluate: Why is help text not enough to repair a button that does nothing?

The action must work. Help can explain a task, but cannot substitute for the required behaviour.

Distinguish: A guide works well with a mouse but cannot be operated by keyboard. What does this demonstrate?

The tested mouse task may work, but a keyboard barrier remains. Do not generalise that observation into an accessibility claim.

Compare and improve a festival interface

  1. Define a visitor, context and session-finding task.
  2. Sketch two interface alternatives with a content hierarchy and return route.
  3. Annotate five relationships between visual choices, principles and audience needs.
  4. Add relevant contextual help and clearly labelled navigation.
  5. Test the task and input methods using a prototype; record observations without leading the participant.
  6. Revise one issue, repeat the check and state a limitation of the evaluation.

Evidence to keep: Two alternatives, navigation map, annotations, prototype and observation/revision record.

Example response: A defensible guide groups title, time and venue consistently and provides understandable routes. Its annotations explain visual relationships. The review reports what was actually tested, a meaningful revision and the remaining limits.

A fresh context: a library kiosk

First-time visitors cannot find where to collect a reserved item. The screen uses attractive icons without text labels.

Propose a hierarchy, relevant help and a test.

Compare with an example response

Group the collection task under a clear heading, label the action and provide short guidance near it. Observe a first-time visitor attempting the task and check relevant input/accessibility needs.

Exit question

Explain one revision using visual choice → principle → user task → observed result.

2. Evaluating devices for a client

Recall

  • Why does more storage not compensate for insufficient RAM?
  • What should be checked before assuming an application runs on a device?

Visual walkthrough

Pass essentials before comparing extras

Pause and predict: Can C be marked passed because it has more RAM?

Show the explanation

No. App support and runtime remain unverified. A larger RAM figure does not provide that evidence.

Try a small change: The task changes to editing the guide in a fixed office. Could B be reconsidered?

Compare your reasoning

Yes. Re-evaluate against the new requirements and evidence. A failure for walking use does not prove failure for a fixed production task.

Try it with support

An advertised “all-day” device has no stated test conditions in the supplied brief. Can you mark a six-hour field-runtime requirement as passed?

Example reasoning: No. Treat the claim as insufficient evidence for that workload. Check the published conditions and run a representative trial or obtain suitable evidence before marking it passed.

Practise and explain

Interpret: Why does “256 GB storage” not prove that 200 GB is available for project files?

The operating system, applications and existing data use space. Check actual available capacity and the required working margin.

Compare: Give one reason a desktop could suit production while a mobile device suits delivery in the field.

A desktop can offer a fixed, larger workspace for editing; mobility can support use between venues. Confirm the actual tasks and compatibility rather than assuming the categories decide everything.

Evaluate: Why should a comparison record an unknown field explicitly?

An unknown is an evidence gap. Treating it as passed can create an unsupported recommendation.

Analyse: How can convergence create both a benefit and a dependency?

Combining camera, schedule and communication reduces separate equipment, but one flat battery may interrupt several tasks. Explain the task-specific benefit and a fallback.

Recommend a device using defensible evidence

  1. Define the volunteer’s tasks, context and essential criteria.
  2. Compare fictional options A, B and C using passed, failed and unverified evidence.
  3. Explain at least two specification-to-usability relationships.
  4. Choose a documented device trend and record source, publication/access dates and the exact claim.
  5. Explain how convergence changes the workflow and identify a dependency.
  6. Write a qualified recommendation, a representative test and a fallback. No purchase or new account is needed.

Evidence to keep: Criteria table, evidence comparison, dated trend record and a justified recommendation.

Example response: A is supported for the fictional walking task. C cannot be treated as passed without the missing evidence. A strong answer connects portability, readability, app support and runtime to tasks, and records a current source for any real trend claim.

A fresh context: a site survey

A team needs to capture notes and photographs outside, then edit a detailed report in the office.

Explain a device/workflow comparison and one convergence dependency.

Compare with an example response

Compare mobile capture with fixed editing, including file transfer, compatibility, readability and runtime. A converged capture device may reduce equipment while concentrating battery and access dependence.

Exit question

Explain one device trade-off and the evidence you would collect before deciding.

3. Rights, collaboration and digital change

Recall

  • Why does attribution not automatically give permission?
  • Why should a communication plan include response expectations and access needs?

Visual walkthrough

Three separate publication questions

Pause and predict: Does a credit answer all three questions?

Show the explanation

No. It helps acknowledge a source but does not settle access, reuse permission or the consequences of a claim.

Try a small change: A private draft becomes a public guide. What should the team revisit?

Compare your reasoning

Review rights, conditions, claims, audience and approval for the changed use. Do not assume a draft arrangement covers public release.

Try it with support

A team credits a photograph in an FOI-released report and plans to reuse it. What remains to be checked?

Example reasoning: Check the rights, terms and other obligations for the intended reuse, including whether the photograph is third-party content. Credit alone and access to the report do not establish unrestricted publication rights.

Practise and explain

Distinguish: How do copyright and a registered design right differ in their focus?

Copyright concerns protected expression and specified uses. A design right concerns qualifying product appearance under its legal scheme. Identify the material and use rather than assuming one label covers everything.

Analyse: Why is “it was already online” not a complete response to a harmful allegation?

Repeating material can be a new publication and extend harm. Accuracy, identification, context and applicable rules still require checking.

Apply: Does Commonwealth FOI mean you can demand all files from a private shop?

No. Its scope concerns specified government-held documents and is subject to limits. Other bodies or jurisdictions may have different frameworks.

Evaluate: Give one reason to combine an in-person planning meeting with online review.

A meeting can resolve initial questions quickly; an online record can support later comments and versioned approval. Check that all participants can access the chosen methods.

Review a fictional festival publication workflow

  1. List three assets or claims and identify the separate rights or accuracy questions.
  2. Write a source and permission record for one fictional asset.
  3. Analyse a fictional reputational-harm scenario without naming real people or repeating real allegations.
  4. Describe the scope of a hypothetical Commonwealth FOI request and one possible limitation; do not submit it.
  5. Compare physical, virtual and hybrid collaboration for a team with different access needs.
  6. Explain how a converged tool changes the workflow and preserve an approval check before publication.

Evidence to keep: A rights/claim checklist, FOI scope explanation and justified collaboration workflow.

Example response: A defensible response checks each asset’s terms and each claim’s basis, explains the government-document scope of Commonwealth FOI and avoids assuming a guaranteed legal outcome. It records review responsibilities and accessible collaboration methods.

A fresh context: a community exhibition

A shared folder contains a government report, a contributor’s photograph and an unverified allegation about an identifiable person.

Describe separate checks before a public display.

Compare with an example response

Check report access/reuse terms, permission and credit for the photograph, and the basis and implications of the allegation. Record responsibilities and seek appropriate clarification rather than treating shared-folder access as publication approval.

Exit question

Explain how a faster shared publishing tool could improve coordination while increasing the importance of review.
